# Architecture

`rs` has three runtime pieces:

1. `rs` in CLI mode: short-lived commands such as `list`, `exec`, `read`, and `transfer`.
2. `rs bridge serve`: a local HTTP daemon on `127.0.0.1:7878`.
3. `rs-bridge-plugin`: a Roblox Studio plugin that registers, heartbeats, long-polls for commands, and posts results.

CLI commands probe `/healthz`. If the bridge is missing, they spawn `rs bridge serve --port <port>` and wait up to three seconds. `rs doctor` is the explicit health command: it checks bridge liveness, registered Studio sessions, installed plugin bundle timestamps, and plugin/CLI protocol compatibility. With `--fix`, it only applies safe local fixes such as starting the bridge or copying the repo-built plugin bundle into the local Roblox Plugins folder; loaded Studio sessions still need a restart to pick up a newer plugin. `rs install-plugin` is the direct install path: it builds with Rojo, copies the bundle, verifies the installed hash/timestamp, and reports connected Studio windows that should be restarted.

Studio sessions are selected by UUID, exact name, or unique case-insensitive substring. If more than one Studio matches, the bridge returns an ambiguity error and the CLI asks the user to disambiguate by UUID. Every Studio registration carries a protocol version, plugin version, and capability list. Before a queued Studio command is dispatched, the bridge verifies that the loaded plugin protocol matches the CLI and returns a clean protocol-mismatch error instead of sending commands to an old plugin that will answer with `unknown command type`.

The bridge stores one queue per Studio session. Simple Studio-backed commands enqueue one plugin command and wait for its result. `export` returns file payloads that the CLI writes to disk after validating every relative path. `import-asset` parses local OBJ/STL/glTF/GLB geometry in the CLI, or asks headless Blender to convert other supported DCC formats to GLB, then sends triangle mesh payloads to Studio. The plugin turns those payloads into welded MeshParts through `EditableMesh`, preserving material names, base colors, texture URI metadata, object hierarchy folders, source pivot attributes, and `SurfaceAppearance` color maps where possible. `import-image` decodes local PNG files in the CLI, sends RGBA pixels to Studio, and the plugin turns them into `EditableImage`-backed `ImageLabel` or `ImageButton` UI. `import-uploaded` creates image/audio Studio instances from existing Roblox cloud asset IDs.

Higher-level commands reuse those primitives instead of bypassing them. `validate`, `repair-tool`, `snapshot`, `create`, `import-ui-pack`, `import-audio`, `upsert-files`, `apply-plan`, `package-update`, `history`, `deps`, and `autopilot-review` are single plugin commands. `validate --fix` composes validation, safe repair, and validation again in Rust so before/after state is visible. `smoke` commands create temporary Studio fixtures through existing endpoints and clean them up after validating the expected behavior; `smoke regression` records a JSON report for the broader weld/package/tool/upload-mock suite. `diff` compares normalized Studio reads or exported folders locally in Rust and can emit a conservative `--fix-plan`; `apply-plan` takes that plan back to Studio with dry-run, approval, filtering, script exclusion, and ownership checks. `sync-folder` scans local files, upserts scripts through the plugin, and routes images/meshes through existing importers, while `sync pull` composes `export` and `serialize` to pull Studio changes back to disk. `batch` runs existing CLI operations from a manifest. `package` combines `export`, direct `serialize`, validation, checksums, and `deserialize` for reimport, with explicit `fail`, `replace`, `merge`, and `rename` conflict modes, package verification, update modes, and zip pack/unpack support. `package import --rehost-images` and `transfer --rehost-images` perform the source serialize first, use Open Cloud asset delivery plus upload to create target-owned copies of referenced images, rewrite the in-memory transfer blob, then deserialize. `transfer` without rehosting enqueues a `serialize` command on the source Studio, then a `deserialize` command on the target Studio with the returned blob; dry-run, replace, and rollback-on-error transfer options map to deserialize controls.

`upload` is intentionally separate from the bridge. It is a CLI-only Roblox Open Cloud client for image, audio, and supported model-container uploads. Uploads can use local Open Cloud profiles, poll operation status with `--wait`, and compose directly into Studio via `--import-to` for image/audio assets. Image rehosting uses the same upload client, and can use a separate `--source-api-key` when source asset delivery and target asset creation are authorized by different keys.

Studio-side mutating flows stamp `rsSourceId`, `rsPackageId` when applicable, `rsImportedAt`, and `rsManagedBy` attributes. Ownership-aware handlers update matching managed instances and refuse to overwrite manual instances unless `force` is explicitly requested. The plugin also records a bounded command audit log in `ServerStorage.rsCommandHistory`; entries include command ID, CLI/protocol version, touched paths, warnings, and rollback snapshots when a handler produced one. `deps` and `publish-check` build on that ownership layer to flag missing/private-risk assets, unowned instances, broken welds, protocol drift, and package checksum drift before sharing or publishing. The Autopilot dock widget is review-only: live preview and apply publish run summaries into Studio so creators can inspect risk, operations, warnings, changed paths, and rollback state without granting approval from the UI.
